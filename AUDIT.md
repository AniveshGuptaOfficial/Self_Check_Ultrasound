## 2. Corrections to the previous audit
- Test count: README said 21, audit said 31; the suite had 36 tests in 8 modules. It now has 56 (41 new/updated + 15 unchanged).
- Quality metrics: README (MAE 1.738, RMSE 2.258) and the audit (MAE 1.516, RMSE 1.838) disagreed; RMSE 1.838 is implausible for r = 0.495. Treat both as unverified until `train_quality_baseline.py` is re-run.
- "1,500 validation frames", "Smooth L1 / Adam": the scripts use 300 val frames by default, `MSELoss` and `AdamW`.
- "94.4% cause accuracy on 5 views": no script produced it (6 views exist) and it was trained and tested on the same synthetic generator. Superseded by `cause_classifier_eval.json`.
- "100% correct triage": the old simulator forced adequacy from ground-truth severity and guaranteed recovery. Not valid evidence; superseded by the leakage-free simulator. Outcomes may now differ (e.g. more attempts, referrals).
- "CNN outperformed classical (50.3% vs 49.7%)": a 0.6-point difference on 300 samples is within noise; the new paired bootstrap reports whether it is significant.
- "0 corrupted / 100% Full HD": the manifest never opened the images; use `build_manifest.py --validate`.

## 3. Evidence classes (keep separate in any paper)
- Real data: manifest, view distribution, expert grades, view/quality baselines, expert-grade AUROC of the cause classifier.
- Synthetic: all fault-diagnosis accuracy on injected faults, all closed-loop trajectories (fault injected, compliance simulated).
- Not done: hardware streaming, probe tracking, in-vivo validation.

## 4. Verdict
Research demonstration: acceptable once the NEEDS RE-RUN items are regenerated and README/AUDIT numbers are replaced with the script outputs.
Journal-level claims: not yet. The cause classifier and guidance are validated only on self-generated faults, the base view classifier is weak, and recovery is simulated.
